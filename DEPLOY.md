# Публикация на GitHub Pages

Бенчмарк работает как статический сайт: сервер, база данных, API-ключи и платный хостинг ему не нужны. По адресу сайта сразу открывается 3D-полигон. Вставленный посетителем код обрабатывается локально в его браузере и не отправляется на GitHub.

## GitHub Actions — основной вариант

1. Создайте репозиторий, например `demolition-bench`.
2. Поместите **содержимое этой папки в корень репозитория**, включая `.github/workflows/pages.yml` и `.gitattributes`. В корне должны быть `package.json`, `index.html`, `solver.js` и папка `engine`.
3. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Отправьте изменения в ветку `main` или `master`. Если код уже был загружен до настройки Pages, запустите **Actions → Publish benchmark to GitHub Pages → Run workflow**.
5. Дождитесь успешного задания `deploy`. Его результат содержит адрес сайта, обычно **`https://ACCOUNT.github.io/demolition-bench/`**.

Каждое следующее изменение в основной ветке автоматически проверяется и публикуется. Для другого имени основной ветки обновите `branches` в workflow.

Для бесплатного GitHub Pages используйте публичный репозиторий; доступность Pages для приватных зависит от тарифа аккаунта.

## Что делает сборка

```powershell
npm test
npm run build
```

Сборка проверяет целостность фиксированного стенда и создаёт папку `dist` с готовой статической страницей. npm-зависимости для этого не нужны. На сайт не попадают локальные отчёты, результаты тестов, `node_modules` и Node.js-сервер.

Публичная страница всегда начинает с исходного базового алгоритма. Локальный эксперимент в `solver.js` не становится опубликованным решением по умолчанию; посетители вставляют код решения прямо на странице.

В `dist` создаётся манифест хешей только браузерных компонентов. Механика проверки и баллы совпадают с локальной версией. Все пути относительные, поэтому сайт работает и в корне домена, и по адресу `/имя-репозитория/`.

## Ручное размещение готовой статики

Можно выложить содержимое `dist` на любой HTTPS-хостинг. Для Pages без Actions поместите это содержимое в корень отдельной ветки `gh-pages` и выберите **Deploy from a branch → gh-pages → /(root)**. Сохраните файл `.nojekyll`.

Не открывайте собранную страницу через `file://`: ES-модули и Worker требуют HTTP(S). На GitHub Pages HTTPS доступен автоматически.

При изменении фиксированных компонентов разработчиком обновите манифест командой `node tools/seal.mjs` и выполните проверки. При изменении правил оценки также обновите версию набора. Модели, проходящие бенчмарк, не должны менять или пересобирать стенд.
