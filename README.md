# Demolition Bench

Рабочий прототип бенчмарка для оптимизации алгоритмов на полигоне разрушений.

Для публикации статического сайта на GitHub Pages см. [DEPLOY.md](DEPLOY.md). Готовая сборка создаётся командой `npm run build`, автоматическая публикация настроена в `.github/workflows/pages.yml`.

**Модель изменяет только `solver.js`.** Сцена, сценарии, проверка и подсчёт баллов находятся в отдельной фиксированной части приложения. Зависимости для запуска не нужны; требуется Node.js 20+ и современный браузер с WebGL 2 для просмотра.

## Запуск

Откройте терминал в этой папке:

```powershell
npm start
```

Откройте **http://127.0.0.1:4173**. Для другого порта установите переменную окружения `PORT`.

На полигоне доступны виадук, башня и пространственная ферма. Мышь синхронно вращает обе сцены. Можно пошагово подрывать конструкцию, включить автоматическое воспроизведение или восстановить исходное состояние. Загрузите JS-модуль модели кнопкой «Загрузить .js», затем запустите бенчмарк. Загрузка файла не меняет файлы на диске.

Во время замера отрисовка приостанавливается. Вычисления выполняются в Worker; прогон можно отменить. Общий лимит операции — 90 секунд. Отчёт экспортируется в JSON.

## Передача задания модели

Передайте модели `MODEL_PROMPT.md` и `solver.js`. Полученный файл загружайте в вашу собственную чистую копию стенда. Модель может полностью переписать реализацию и использовать любые структуры данных внутри модуля.

Режим оценки — **одна попытка**: новая сессия для каждой модели, один окончательный ответ, без запуска кода, тестов, браузера, поиска в интернете и делегирования. Разрешены чтение выданных материалов, внутреннее рассуждение и выдача готового файла. Не передавайте результаты проверки обратно модели для исправлений: проверяется именно первая финальная версия. Для соблюдения режима отключите у тестируемой модели инструменты выполнения, браузер и сетевой доступ; текст промпта сам по себе не блокирует их технически.

В комплекте `solver.js` — точная копия фиксированного базового алгоритма. Он использует типизированные массивы, очередь без `shift()`, повторно используемые буферы и метки посещения. После каждого изменения полностью пересчитывает достижимость от опор: это разумная отправная точка с возможностями для улучшения.

## Контракт

```js
export function createSolver({ nx, ny, nz, solid, anchors }) {
  // Создайте независимое состояние одной конструкции.
  return {
    step(removed) {
      // Примените повреждение, найдите и удалите неподдерживаемые блоки.
      return new Uint32Array(/* IDs всех отделившихся блоков */);
    }
  };
}
```

- `nx`, `ny`, `nz` — целые положительные размеры сетки.
- Индекс: **`id = x + nx * (z + nz * y)`**. Y направлен вверх.
- `solid: Uint8Array` длиной `nx*ny*nz`: 1 — блок присутствует, 0 — пусто.
- `anchors: Uint8Array` той же длины: 1 — закреплённый блок. Опоры могут быть на любой высоте. Начальные опоры являются занятыми клетками.
- Входные массивы принадлежат экземпляру алгоритма: их можно изменять. Остальные экземпляры и эталон имеют независимые копии.
- `removed: Uint32Array` содержит допустимые индексы повреждаемых клеток. Возможны повторы, уже пустые клетки и пустые массивы.
- Сначала одновременно удаляются все `removed`. Затем находится множество оставшихся блоков, не соединённых ни с одной оставшейся опорой через **шесть общих граней**. Касания рёбрами и углами не передают опору; переход через границу строки/слоя запрещён.
- Возвращается ровно это множество в `Uint32Array`: порядок произвольный, дубликаты запрещены. Уже пустые и непосредственно взорванные клетки в результат не входят.
- Возвращённые блоки также удаляются из состояния алгоритма перед следующим `step`.
- Опоры можно разрушать. Они не восстанавливаются и не закрепляют другие клетки на расстоянии.
- Даже первый пустой шаг должен удалить изначально неподдерживаемые компоненты.
- Буфер результата можно переиспользовать: проверяющая сторона считывает его до следующего вызова.
- `createSolver` и `step` синхронны. На каждом повторе создаётся новый независимый экземпляр. Будущие повреждения ему не передаются.

В версии 1 блоки только удаляются; добавление и повторное закрепление не входят в задачу.

## Что именно моделируется

Это **дискретная связность конструкции**, а не расчёт строительной прочности. Достаточно любого пути по граням к опоре; масса, изгиб, момент сил и предел прочности здесь не используются.

Обе сцены показывают один сценарий: слева — результат независимого эталона, справа — результат модуля модели. Красным выделяются ошибочно отделённые или оставленные блоки. После первого расхождения воспроизведение останавливается на соответствующем шаге.

Падение отделившихся блоков — декоративная анимация. Блоки покидают расчётную конструкцию, визуальные обломки исчезают и не становятся новыми опорами. Маленький полигон служит для просмотра; скорость измеряется на трёх более крупных конструкциях.

## Проверка и баллы

1. Независимый эталон строит компоненты связности методом union-find. Базовый алгоритм использует обход от опор; реализации не разделяют вычислительное ядро.
2. Проверяются 24 граничных и воспроизводимых случайных случая: отсутствие опор, удаление опор, несколько путей к опоре, диагональные касания, границы сетки, повторные и пустые повреждения, случайные структуры с произвольными опорами.
3. Для каждого большого сценария заранее вычисляется правильный результат каждого шага.
4. Оба алгоритма проходят прогрев. Затем выполняются 5 серий с чередованием порядка «база/кандидат» и «кандидат/база».
5. В каждом замеряемом шаге результат сравнивается с эталоном, включая все идентификаторы и отсутствие дубликатов. Ошибка означает `invalid`, баллы не вычисляются.
6. Измеряются синхронный вызов `createSolver` и все `step`. Подготовка входных копий, вычисление эталона, проверка результата, импорт модуля, UI и рендеринг исключены. Выделения памяти и работа, выполняемые самим модулем в этих вызовах, входят в замер.

Для каждой сцены берётся медиана полного времени `createSolver + сумма step`. Итоговое ускорение — геометрическое среднее отношений «база / кандидат» по сценам.

```text
score = 100 * log2(speedup)
```

Двукратное ускорение даёт +100; одинаковая скорость — 0; двукратное замедление — −100. Подбаллы времени построения и шагов в отчёте полезны для диагностики; их отдельные медианы не обязаны в сумме совпасть с медианой полного времени.

**Ноль — математическая точка отсчёта.** Копия базового алгоритма может получить небольшой положительный или отрицательный балл из-за JIT, GC и фоновой нагрузки. Смотрите сырые серии, повторяйте замеры, не ранжируйте близкие результаты по одному прогону. Три повторения доступны в CLI для быстрой проверки; для сравнения используйте 5–15.

Сравнивайте на одном устройстве и в одной версии среды. Относительное время уменьшает влияние железа, но не устраняет его. Браузерные и Node.js-отчёты не следует смешивать в одном рейтинге. Если вкладка скрыта во время измерения, лучше повторить прогон.

## Без графики

```powershell
node cli.mjs --candidate solver.js --seed 314159 --repeats 5 --out result.json
node cli.mjs --candidate other-model.js --seed 724811 --repeats 9 --out other-result.json
```

CLI использует то же ядро проверок и замеров в отдельном потоке. `--timeout 90` задаёт лимит времени в секундах. Код выхода: 0 — корректно, 1 — неверный результат, 2 — ошибка модуля или превышение лимита. Результат содержит seed, версию набора, хеш исходника, среду выполнения, все серии, медианы и баллы.

## Файлы

| Файл | Назначение |
|---|---|
| `solver.js` | Единственный изменяемый файл модели |
| `MODEL_PROMPT.md` | Готовое задание для модели |
| `engine/baseline.js` | Фиксированная база для относительного времени |
| `engine/oracle.js` | Независимая проверка |
| `engine/scenarios.js` | Геометрия, повреждения, генератор по seed |
| `engine/benchmark.js` | Контракт, измерения и оценка |
| `render.js`, `app.js`, `index.html`, `style.css` | Фиксированный просмотрщик |
| `worker.js`, `cli.mjs` | Запуск логики отдельно от интерфейса |
| `manifest.json` | Контроль хешей фиксированных файлов |

Хеши обнаруживают случайное изменение стенда; это не защита от того, кто меняет одновременно код и манифест. Проводите оценку в собственной чистой копии. Worker позволяет остановить зависший расчёт, но не является защитной песочницей для произвольного враждебного кода.
