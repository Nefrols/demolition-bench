# Demolition Bench

**[Пройти тест в браузере →](https://nefrols.github.io/demolition-bench/)**

Один промпт, одна попытка модели, один фиксированный тест. Ничего устанавливать или скачивать не нужно.

1. Нажмите **«Скопировать промпт + solver»**. Стартовый код уже включён в задание.
2. Передайте текст модели в новой сессии. Модель выдаёт одно готовое решение без браузера, поиска, выполнения кода и исправлений после оценки.
3. **Вставьте код на страницу.** Проверка начинается автоматически. Можно вставлять вместе с ограждением ` ```js `.

Ускорение, баллы и время базы/решения появляются поверх 3D-сцены. Сцену можно вращать мышью или касанием, а анимацию — повторить. Справка открывается плавающей кнопкой **Help**. Истории, загрузок файлов, профилей и настроек нагрузки нет. Код и результаты не сохраняются.

## Что проверяем

Модель оптимизирует синхронный JavaScript-модуль динамической связности. Конструкция разрушается и восстанавливается, опоры меняются, компоненты соединяются и отделяются. Для каждого отделившегося фрагмента нужен точный состав и 12 целочисленных характеристик: идентификатор, число клеток, суммы координат, поверхность с учётом полостей и границы.

Сложность задают альтернативные пути к опорам, циклы, узкие соединения, полости, порядок транзакций и сохранение состояния. Метод решения свободный. Фиксированная база уже использует типизированные массивы, маски границ, очереди и переиспользование памяти.

Полный контракт: [MODEL_PROMPT.md](MODEL_PROMPT.md). API солвера остался V2. Набор измерений — **demolition-2.1.0**; его баллы нельзя смешивать с 2.0 или V1.

## Компактный и одинаковый тест

Одна конструкция **32×24×24 = 18 432 ячейки**, 24 транзакции. Перед замером — 33 небольших проверки корректности. Размеры, данные и число повторений фиксированы для всех решений и устройств. Нет адаптивного наращивания работы, миллионов клеток или стресс-профилей.

После прогрева выполняются пять серий по четыре свежих экземпляра каждого солвера, порядок базы и кандидата чередуется. Для результата берётся медиана среднего полного времени экземпляра в серии. Это фиксированные повторы для устойчивости измерения, а не увеличение задачи для медленных устройств.

Весь прогон ограничен **120 секундами**, включая импорт модуля, проверки и подготовку. Медленный или зависший код останавливается без баллов. Лимит ограничивает ожидание; он не гарантирует, что любой алгоритм успеет на любом устройстве. При скрытии вкладки измерение прерывается. Вставка нового кода также отменяет старый прогон.

## Корректность и время

Независимый эталон использует union-find, база — обход от опор. Проверяется каждый ID и каждое поле компонента на каждом шаге всех серий. Любая ошибка исключает оценку скорости. Конечный набор проверок не заменяет доказательство корректности на всех допустимых входах.

В измеряемое время входят `createSolver` и все `step`, включая память, выделяемую внутри них. Подготовка входных копий, эталон, сравнение ответов, UI и отрисовка исключены. Во время измерения графика приостановлена. Предвычисления вне API, общие кеши между экземплярами и зашитые ответы запрещены.

```text
ускорение = время базы / время решения
баллы = 100 × log2(ускорение)
```

Одинаковая скорость — 0, 2× — +100, 4× — +200, замедление вдвое — −100. Потолка баллов нет. Сравнивайте на одном устройстве и в одной версии браузера: относительное время не устраняет влияние железа, JIT и GC. Размах серий более 25% медианы отмечается как шум. Малые различия не следует считать надёжным преимуществом.

Сцена показывает дискретную связность, а не строительную прочность. Падение обломков — иллюстрация вычисленного ответа.

## Репозиторий и публикация

Основной продукт — статическая страница GitHub Pages. Модель меняет только текст солвера; сцена, эталон и измеритель фиксированы. Хеши защищают от случайного изменения стенда, но не от намеренной подмены кода вместе с манифестом. Worker позволяет остановить зависший расчёт, но не служит защитной песочницей для враждебного кода. One-shot режим требует отключения инструментов у тестируемой модели.

Для сопровождающих: `npm test` проверяет ядро, лимиты, CLI и статическую сборку; `npm run build` создаёт `dist`. GitHub Actions автоматически тестирует и публикует изменения `main`. `npm start` и `cli.mjs` — вспомогательные инструменты разработки, для прохождения теста не нужны. Браузерные проверки — `node tests/browser.mjs` с Playwright; адрес задаётся через `BENCH_URL`. После намеренного изменения фиксированных файлов обновляется `manifest.json` командой `node tools/seal.mjs`.

[Архив V1](https://nefrols.github.io/demolition-bench/v1/) сохранён для старых результатов. Предыдущий интерфейс V2 остаётся в истории Git.
