# Demolition Bench V2

**[Открыть полигон](https://nefrols.github.io/demolition-bench/)** · **[Архив V1](https://nefrols.github.io/demolition-bench/v1/)**

Бенчмарк оптимизации кода: модель переписывает один `solver.js`, а фиксированный стенд проверяет точный ответ и измеряет время. V2 — динамическая связность трёхмерной конструкции с разрушением, восстановлением, переносом опор и расчётом характеристик фрагментов. API и баллы V1 и V2 несовместимы; старые решения запускаются в архиве.

## Как пользоваться

1. Нажмите «Скопировать задание + код» и передайте текст модели в новой сессии. При необходимости скачайте `solver.js` отдельно.
2. Получите единственный финальный файл. Перетащите его на страницу, укажите имя модели.
3. Выберите профиль и запустите бенчмарк. Предпросмотр показывает эталон слева и кандидата справа, поддерживает вращение, воспроизведение, шаги и перемотку.
4. Смотрите точность, баллы, таблицу и кривую масштабирования. Сохраните JSON; до 20 отчётов хранятся локально без исходников. История меняет отображаемый отчёт, но не загруженный солвер.

Режим модели — **одна попытка**: без браузера, поиска, выполнения кода, тестов, делегирования и исправлений после обратной связи. Полный текст — [MODEL_PROMPT.md](MODEL_PROMPT.md). Отключите соответствующие инструменты у модели: промпт не блокирует их технически. Повторное измерение того же готового файла для оценки шума допустимо; возвращать результаты модели для исправления нельзя. Результаты с инструментами отмечайте отдельно.

## Что стало сложнее

Вместо удаления блоков из одной неизменной конструкции нужно обрабатывать онлайн-транзакции: удаление, строительство, снятие и добавление закреплений. Меняются связность, пути к опорам и состав компонентов. Для каждого оторвавшегося фрагмента требуются число блоков, суммы координат, точная площадь поверхности с учётом полостей и ограничивающий параллелепипед.

Четыре семейства сочетают разные плотности и топологии: аркология, транспортный узел, островные опоры, пористый монолит. Локальные изменения чередуются с разрезами, сменой опор, множеством фрагментов, полным обрушением и повторной сборкой. Быстрые локальные обновления, массовые обходы, размещение данных в памяти и стоимость инициализации влияют на итог. Метод решения не регламентируется.

База уже использует типизированные массивы, список занятых клеток, маски границ, повторно используемые очереди и метки посещения. Пустые транзакции пропускает. После реального изменения выполняет глобальный обход от опор и обход отделившихся компонентов. Это рабочая оптимизированная отправная точка, а не намеренно квадратичный алгоритм.

| Профиль | Размеры | Нагрузок | Шагов на нагрузку | Лимит браузера |
|---|---|---:|---:|---:|
| Разведка | S / M | 8 | 28 | 3 минуты |
| Основной | S / M / L | 12 | 44 | 10 минут |
| Стресс | M / L / XL | 12 | 60 | 20 минут |

S: 32×24×32; M: 64×48×64; L: 112×80×96; XL: 160×112×128 (2 293 760 ячеек). Занятость зависит от семейства. Предпросмотр меньше измеряемых конструкций. Количество серий выбирается отдельно. Стресс требует больше времени и памяти; на слабых устройствах начните с разведки.

## Точный контракт

```js
export const apiVersion = 2;
export function createSolver({nx, ny, nz, solid, anchors}) {
  return {
    step({remove, add, anchorOff, anchorOn}) {
      return {detached: new Uint32Array(), components: new Uint32Array()};
    }
  };
}
```

Индекс `x + nx * (z + nz * y)`. `solid` и `anchors` — приватные `Uint8Array`. Все четыре поля транзакции — приватные `Uint32Array` допустимых индексов; возможны повторы и пустые массивы. Размеры 1–256, произведение не больше 4 194 304. Входные массивы разрешено изменять.

Порядок: удалить клетки и их закрепления → добавить отсутствующие клетки без закреплений → снять закрепления → закрепить только занятые клетки. Добавление существующей клетки её не меняет. Проверка связности происходит после всех четырёх фаз. Связь передают шесть граней, без перехода через границы сетки. Каждый оставшийся блок без пути к любой опоре возвращается в `detached` и удаляется из состояния. Изначально висящие блоки падают даже на первом пустом шаге. Удалённые блоки можно построить вновь.

`components` содержит по 12 uint32 на каждый отделившийся компонент:

```text
minId, count, sumX, sumY, sumZ, surfaceFaces,
minX, minY, minZ, maxX, maxY, maxZ
```

Площадь — число граней к воздуху или за границу сетки, включая внутренние полости; вычисляется после транзакции, до удаления фрагментов. Границы включительные. Порядок ID и записей произвольный, дубликаты запрещены. Ответ точный; буферы можно переиспользовать после считывания. Поддерживаемые компоненты в ответ не входят. Полные семантика и пример в промпте.

Это модель **связности**, а не строительной прочности: массы, напряжений и изгиба нет. Падающие обломки — визуальная анимация, они не участвуют в последующих вычислениях. Ошибки ID подсвечиваются; неверная статистика компонента тоже останавливает предпросмотр.

## Проверка и измерения

Независимый эталон использует union-find и агрегирование компонентов; база — обходы. Перед измерениями проверяются 33 сценария: границы, порядок транзакций, полости, длинная цепь, несколько опор и случайные последовательности. Затем проверяется каждый ответ каждого шага каждого замера, включая все 12 полей. Один неверный ответ означает `invalid`, без баллов. Это конечный набор тестов, не доказательство корректности на всех входах.

Измеряются только синхронные `createSolver` и `step`, включая их выделения памяти. Вне таймера: импорт модуля, подготовка копий, расчёт эталона, проверка, интерфейс и рендеринг. Отрисовка приостановлена, вычисления идут в Worker с отменой и лимитом времени. Предвычисления вне API, межэкземплярные кеши, распознавание тестов и вмешательство в стенд запрещены контрактом.

После прогрева идут серии с чередованием порядка база/кандидат. Для малых нагрузок серия объединяет до 8 свежих экземпляров, одинаковое количество для обоих алгоритмов, с целевым временем базы около 40 мс. Берётся медиана среднего полного времени экземпляра по сериям. Построение и шаги сохраняются отдельно, также сохраняются фазы и сырые серии. Их отдельные медианы могут не складываться в медиану общего времени. p95 относится к отдельным вызовам step.

```text
speedup = геометрическое среднее (время базы / время кандидата) по нагрузкам
score = 100 × log2(speedup)
```

База = 0; 2× = +100; 4× = +200; 8× = +300; 0,5× = −100. Верхней границы баллов нет. У каждой фиксированной задачи есть практический предел ускорения; новая задача расширяет пространство оптимизаций, но не гарантирует разрыв между конкретными моделями.

Сравнивайте один профиль, seed, количество серий, устройство и версию браузера/Node.js. Относительные времена уменьшают влияние железа, но не устраняют его. Копия базы может получать небольшие плюсы/минусы из-за JIT, GC и фоновой нагрузки. Размах серий свыше 25% медианы помечается как шум. Повторяйте замер того же файла, если результаты близки. Для устойчивого рейтинга используйте несколько заранее выбранных seed для всех моделей.

График показывает реальное время с логарифмической осью Y. «Все семейства» — геометрическое среднее времени по семействам для каждого размера. Предыдущий отчёт добавляется на график только при совпадении набора, профиля, seed, серий и записанной среды. Строка браузера и число потоков не идентифицируют устройство однозначно — это дополнительно контролирует оператор. Импортированные отчёты валидируются по формату и согласованности баллов, но не имеют серверной подписи.

## Локальный запуск и CLI

Node.js 20+, современный браузер, WebGL2 для просмотра. Runtime-зависимости не нужны.

```powershell
npm start
# http://127.0.0.1:4173
node cli.mjs --candidate solver.js --profile quick --seed 314159 --repeats 3 --out result.json
node cli.mjs --candidate model.js --profile stress --repeats 5 --timeout 1200 --out result-stress.json
npm test
npm run build
```

CLI: код выхода 0 — корректно, 1 — неверный ответ, 2 — ошибка модуля/таймаут. Лимит по умолчанию 600 секунд. JSON включает версию набора, seed, профиль, SHA256 солвера, среду и измерения. Браузерный тест: установите Playwright без сохранения зависимости, затем `node tests/browser.mjs` при запущенном сервере; `BENCH_URL` задаёт другой адрес, `PLAYWRIGHT_EXECUTABLE_PATH` — путь к Chromium.

Сборка создаёт статический `dist`, включая архив `dist/v1`. GitHub Actions публикует его в Pages; см. [DEPLOY.md](DEPLOY.md). Для разработки фиксированные файлы проверяются по `manifest.json`. После намеренного изменения стенда выполните `node tools/seal.mjs`; изменение семантики или нагрузки требует новой версии набора. `solver.js` в проверку хешей не входит; опубликованный стартовый файл всегда копируется из базы.

Хеши обнаруживают случайные изменения, а не подмену одновременно кода и манифеста. Worker позволяет прервать зависание, но не является защитной песочницей для враждебного кода. Оценка должна проходить на чистом стенде под контролем оператора.
